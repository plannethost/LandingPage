01 / DIAGNOSIS

Mulai dari lapisan yang paling dekat

Tentukan terlebih dahulu apakah error terjadi saat menarik image, menyalakan container, mengakses web, terkoneksi ke database, atau membaca SNMP dari perangkat. Langkah ini mempersempit penyebab tanpa mengubah konfigurasi yang sudah bekerja.

03

SNMP & OID

02 / ERROR CATALOG

Cari pesan error

Ketik sebagian pesan error untuk memfilter panduan di bawah. Buka setiap entri untuk melihat penyebab yang perlu dicek dan tindakan yang dapat dilakukan.

denied: permission_denied: read_packageGHCR / PACKAGE · GHCR menolak akses ke image atau package.

Periksa nama image: ghcr.io/ramonveredic/linnms untuk production, atau ghcr.io/ramonveredic/linnms-staging untuk staging. Jika pull package private, lakukan docker login dengan izin baca. Jika terjadi saat publish GitHub Actions, periksa Package settings → Manage Actions access agar repo penerbit memiliki akses package yang sesuai.

manifest unknown / not foundGHCR / IMAGE · Tag image belum ada atau nama registry salah.

Cek apakah workflow release telah berhasil memublikasikan image dan tag versi yang diminta. Gunakan nama baru linnms, bukan nama package lama. Jangan menganggap tag latest sudah tersedia sebelum release berhasil.

port is already allocated / address already in useDOCKER · Port host sudah digunakan service lain.

Periksa binding Compose dan proses yang memakai port contoh 84/4143. Ganti published port atau hentikan service konflik sesuai prosedur operasional.

Container restarting / unhealthyDOCKER · Service tidak sehat setelah startup.

Mulai dari docker compose ps, lalu lihat logs --tail=100 app dan logs --tail=100 db. Pastikan image dapat ditarik, volume writable, lingkungan sesuai, dan MariaDB healthy sebelum menelusuri koneksi perangkat.

Can't connect to local server through socketDATABASE · Socket MariaDB tidak ditemukan atau DB belum siap.

Cek status container db, healthcheck MariaDB, dan mount bersama /run/mysqld. Periksa izin direktori, path volume dan startup DB. Jangan menghapus volume data sebagai langkah pertama.

Access denied for userDATABASE · Username/password database ditolak.

Tinjau variabel lingkungan, user dan hak akses MariaDB. Konfigurasi contoh mungkin tidak cocok untuk sistem existing. Jangan mencetak kata sandi ke log atau issue publik.

Timeout: No Response from ...SNMP / NETWORK · Agen tidak membalas request SNMP.

Uji ping/rute seperlunya, firewall UDP 161, VLAN manajemen, ACL SNMP perangkat, versi SNMP, community/credentials dan alamat sumber. Jika SNMPv3, periksa autentikasi serta privacy protocol.

No Such Object / No Such InstanceSNMP / OID · OID atau indeks tidak dikenali oleh agen.

Periksa apakah menggunakan scalar .0 atau kolom dengan ifIndex. Cek MIB, perangkat, firmware dan akses ke cabang OID yang diminta. Mulailah dari sysObjectID.0 dan ifName jika didukung.

Hasil snmpwalk kosong / endOfMibViewSNMP / OID · Tidak ada instance yang dapat dilalui di cabang tersebut.

Coba OID induk yang lebih tepat, periksa ACL dan dukungan firmware. Beberapa cabang enterprise ZTE/HIOSO hanya ada pada model tertentu. Jangan menganggap semua vendor punya indeks yang sama.

502 Bad Gateway / HTTP tidak terbukaWEB / PROXY · Reverse proxy atau layanan HTTP belum siap.

Pastikan container app berjalan, mapping port benar, firewall mengizinkan akses, dan reverse proxy mengarah ke host/port yang tepat. Lakukan pemeriksaan curl -I dari host terlebih dahulu.

Tidak ada pesan error yang cocok. Coba istilah lebih umum.
03 / OPERATOR TOOLS

Perintah pemeriksaan singkat

Gunakan utilitas yang tersedia pada host, lalu gunakan nama service sesuai deployment yang dipakai. Perintah berikut memakai berkas Compose resmi dan utilitas SNMP pada host.

Lihat service & log
docker compose -f deploy/compose.yaml config
docker compose -f deploy/compose.yaml ps
docker compose -f deploy/compose.yaml logs --tail=100 app
docker compose -f deploy/compose.yaml logs --tail=100 db
Periksa port host dan HTTP
ss -lntup
curl -I http://SERVER_IP:84/
Uji OID paling dasar
snmpget -v2c -c 'COMMUNITY' DEVICE_IP 1.3.6.1.2.1.1.2.0
snmpget -v2c -c 'COMMUNITY' DEVICE_IP 1.3.6.1.2.1.1.3.0
!

Jangan membagikan token registry, SNMP community, password database, IP private yang sensitif, atau konfigurasi rahasia dalam laporan publik.

04 / INCIDENT NOTES

Catat konteks sebelum eskalasi

Untuk analisis lebih lanjut, simpan: waktu insiden, versi image, arsitektur host, perubahan konfigurasi terakhir, nama service yang bermasalah, pesan error yang sudah disamarkan, hasil perintah diagnosis dan dampak terhadap perangkat. Jangan ubah banyak variabel sekaligus.
