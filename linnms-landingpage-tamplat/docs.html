01 / PREPARATION

Persyaratan instalasi

Periksa komponen berikut sebelum menyalakan production. Nilai konfigurasi dalam contoh deployment harus disesuaikan dengan sistem dan kebijakan jaringanmu.

✓

Docker & Compose

Docker Engine dan plugin Docker Compose terpasang; server dapat mengakses GHCR atau image telah disediakan secara offline.

✓

Jalur jaringan

Host dapat mencapai IP manajemen perangkat. Pastikan UDP 161, SNMP community / credential, ACL dan routing sesuai.

✓

Penyimpanan persisten

Sediakan volume state aplikasi dan data MariaDB. Jangan membuang volume saat update atau pemecahan masalah.

✓

Keamanan akses

Ganti kredensial contoh, batasi akses web manajemen, dan pertimbangkan terminasi HTTPS melalui reverse proxy.

!

Template Compose dari repository production masih memuat konfigurasi database yang ditujukan bagi lingkungan terisolasi. Audit dan amankan kredensial, jaringan, serta eksposur port sebelum digunakan secara nyata.

02 / REGISTRY

Image GHCR dan versi

LINNMS Production menggunakan nama image di bawah. Gunakan tag versi yang benar-benar sudah diterbitkan untuk deployment yang membutuhkan rollback konsisten.

Format image production
ghcr.io/ramonveredic/linnms:latest
ghcr.io/ramonveredic/linnms:X.Y.Z

Contoh X.Y.Z adalah placeholder, bukan tag yang pasti tersedia. latest hanya tersedia setelah proses publikasi release berhasil. Untuk package private, login ke GHCR memakai token yang memiliki akses baca package.

Autentikasi registry jika package private
echo "$GHCR_READ_TOKEN" | docker login ghcr.io   --username GITHUB_USERNAME --password-stdin
✓

Simpan token di password manager atau sistem secret, bukan di Compose dan bukan di dokumentasi publik.

03 / DEPLOYMENT

Jalankan Docker Compose

Gunakan berkas deployment resmi dari LINNMS / deploy. Contoh Compose menyediakan service aplikasi dan MariaDB. Pastikan path, image, port dan volume sudah disesuaikan.

Clone dan jalankan
git clone https://github.com/RamonVeredic/LINNMS.git
cd LINNMS
docker compose -f deploy/compose.yaml config
docker compose -f deploy/compose.yaml pull
docker compose -f deploy/compose.yaml up -d
docker compose -f deploy/compose.yaml ps
Port host pada contoh84 → 80 / 4143 → 443Periksa benturan port dan aturan firewall.
Volume persistent/config · /var/lib/mysqlLokasi di host tergantung berkas Compose yang digunakan.

Variabel LINNMS_IMAGE di Compose standar dapat digunakan untuk menetapkan image versi tertentu saat deployment.

Gunakan tag versi tertentu
LINNMS_IMAGE=ghcr.io/ramonveredic/linnms:X.Y.Z   docker compose -f deploy/compose.yaml up -d
!

Jangan menjalankan database berpassword kosong pada lingkungan yang dapat diakses jaringan tidak tepercaya. Review setting container database sebelum menjalankan perintah di atas.

04 / DEPLOYMENT

Instalasi melalui CasaOS

Gunakan file deploy/compose.casaos.yaml dari repository production. Buka menu instalasi Compose/custom install di CasaOS sesuai versi CasaOS yang kamu gunakan.

01
Impor Compose

Pilih contoh production, bukan staging. Pastikan image mengarah ke ghcr.io/ramonveredic/linnms.

02
Sesuaikan host path

Contoh CasaOS memakai /DATA/AppData/linnms/state, /DATA/AppData/linnms/database dan /DATA/AppData/linnms/run.

03
Validasi akses

Cek hak akses volume, host port, konektivitas database, lalu jalankan container.

05 / VERIFICATION

Pemeriksaan setelah startup

Pastikan status container aplikasi dan database sehat. Cek HTTP dari host, kemudian jalankan uji SNMP melalui jalur jaringan yang dapat menjangkau perangkat.

Cek container, database & web
docker compose -f deploy/compose.yaml ps
docker compose -f deploy/compose.yaml logs --tail=80 app
docker compose -f deploy/compose.yaml logs --tail=80 db
curl -I http://SERVER_IP:84/
Uji SNMP standar
snmpget -v2c -c 'COMMUNITY' DEVICE_IP 1.3.6.1.2.1.1.3.0
snmpwalk -v2c -c 'COMMUNITY' DEVICE_IP 1.3.6.1.2.1.2.2.1.8

Apabila perintah memberi Timeout: No Response from..., periksa firewall/ACL, alamat perangkat, versi SNMP dan community. Rujuk penanganan error.

06 / MAINTENANCE

Update, backup dan rollback

Sebelum update, catat versi image yang dipakai dan cadangkan state serta database secara konsisten. Gunakan tag versi tetap untuk mengurangi risiko perubahan tak terduga.

Review dan terapkan update
# Cadangkan state dan database sebelum langkah ini
docker compose -f deploy/compose.yaml config
docker compose -f deploy/compose.yaml pull
docker compose -f deploy/compose.yaml up -d
docker compose -f deploy/compose.yaml ps
!

Jangan memakai docker compose down -v untuk mengatasi error startup: opsi tersebut menghapus named volumes, termasuk data yang mungkin belum dicadangkan.
